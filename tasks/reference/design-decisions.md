# modelviewprojection design decisions (digest)

**Reference document** — a distilled index of the durable design decisions and rationale, pulled from the archived task docs so they aren't lost in the don't-trawl archive. Not a task; update in place. Last updated 2026-07-30.

This complements `CLAUDE.md` (the current rules) by recording **why** each rule exists and **where** it was decided. Paths are repo-relative under `tasks/archive/`. Where a decision was parked, declined, or reverted, that is stated — those are the ones most likely to be re-litigated. When two docs disagree, the later date and `CLAUDE.md` win; the earlier entry is kept for the reasoning.

## Math library & gacalc integration

- **mvp's home-grown vector/transform math was deleted; gacalc's `Vector1/2/3` + transform layer became *the* vector type.** "Switch the type, not just import helpers" (Option B) to remove maximal duplication; a compat `Vector3D` subclass was rejected as reintroducing a second vector type. Gotchas that bite every consumer: fields are `coeff_e_1/2/3` (not `.x/.y/.z`); `dot()` returns a *multivector* → `.scalar_part()`; `cross` is `(v^w).dual()` (check sign vs CCW tests); `__iter__` yields per-blade multivectors, so vertex unpacking must use the graded types. (Until gacalc 0.0.15, sourcing bare `e_1` from `gacalc.g2` yielded a full `G2` — losing the graded type + fast closed-form sandwich — so `Vector2.e_1` was mandatory; **as of 0.0.15 the module constants are graded, so `from gacalc.g2 import e_1` is a `Vector2` and the demos import it unqualified — see the unqualified-imports entry below.**) Book Phase 4 (teach gacalc vectors in ch05/06/14) relocated to `tasks/book-rotate-prose-update.md`. (`2026/07/09/gacalc-math-migration.md`)

- **Graded basis constants are imported *unqualified* (`from gacalc.g2 import e_1`), not written `Vector2.e_1` (2026-08-04, needs gacalc ≥ 0.0.15).** 0.0.15 made the module constants graded, so the unqualified form keeps the `Vector2`/`Vector3` type and reads like the printed math (`3*e_1 + 4*e_2` ↔ `3e₁ + 4e₂`). Swept **545 sites across 19 files** (demos 05–18, `nbplotutils`, `generate_plots`, `framebuffer`, `notebooksrc`); the `Vector2`/`Vector3` *class* import stays for constructors + annotations. **Exception — files using BOTH 𝒢₂ and 𝒢₃ stay qualified:** `from gacalc.g2 import e_1` and `from gacalc.g3 import e_1` both bind bare `e_1` (collision on `e_1`/`e_2`/`e_12`; `e_3`/`e_13`/`e_23`/`e_123` are 𝒢₃-only and safe) — the three are `mathutils.py`, `notebooksrc/plot2d.py`, `assignments/demo02/plot2d.ipynb`. Classmethods (`.project`/`.reflect`) have no module form and stay qualified. (`2026/08/04/unqualify-graded-basis-imports.md`)

- **gacalc 0.0.16 dropped the dimension suffix from the generated types; mvp adopted it by direct-import / module-qualify, and `mathutils` was de-facaded (2026-08-13).** `Vector2`/`Vector3` → **`Vector`**, `Bivector3` → `Bivector` — the dimension now lives in the *module*, so single-dimension files import the bare `Vector` from their module (`from gacalc.g2 import Vector`) and the multi-dimension files module-qualify (`import gacalc.g2 as g2` → `g2.Vector`); **aliasing (`Vector as Vector2`) was rejected** for re-adding the suffix locally. Reprs are now module-qualified (`g2.Vector(coeff_e_1=…)`), so mvp doctests showing a gacalc repr updated to that form. **De-facade:** the 12 SuperBible ports that still pulled `Vector3` *through* `mathutils` now import `from gacalc.g3 import Vector` directly, so `mathutils` re-exports **no** gacalc type (matching its docstring). Two gotchas worth keeping: a book codemod must be **idempotent — prove it by running twice** (a facade-import split re-inserted a duplicate gacalc import on re-runs until guarded); and to inspect gacalc's real types/reprs/marker names, **`pip install gacalc==<v>` and read `site-packages/gacalc/`** — the wheel/sdist ship the generated `g*.py` pre-baked, so never `pip download --no-binary`/clone/`make generate` (see `CLAUDE.md` › the gacalc-source note). The ch05 book doctests were also fixed — they relied on `Vector2(x=, y=)` kwargs gacalc never accepted (fields are `coeff_e_1`/`coeff_e_2`; x/y are read-only properties). Pin + `Dockerfile ARG GACALC_VERSION` → 0.0.16; gates green (104 pytest; `make html` doc-region anchors all resolve, Sphinx built with no `:term:` breakage). Surfaced separate pre-0.0.15 drift: ch10's illustrative doctests still call the renamed `is_close` (`tasks/book-ch10-isclose-doctest-drift.md`). (`tasks/archive/2026/08/13/adopt-unsuffixed-gacalc-graded-types.md`, `defacade-mathutils-gacalc-reexports.md`)

- **gacalc 0.0.15 renamed `is_close` → `isclose` and its tolerances now default to `0.0` (exact); mvp's 36 test callers pass `rel_tol=1e-5, abs_tol=1e-5`.** That's the old numpy default and gacalc's in-tree convention; a bare `.isclose(x)` is now exact equality *by design* (see gacalc `tasks/reference/approximate-float-equality.md`). A public rename + default change shipped with no changelog, breaking mvp silently on the pin bump — motivated the gacalc `changelog-for-breaking-api-changes` task. (`2026/08/04/gacalc-0015-isclose-tolerance-migration.md`)

- **`mathutils.py` is now only mvp-local graphics helpers; the pass-through façade re-exports were removed (2026-07-21).** Bill's rule: no re-export façade — anything referenceable in gacalc imports directly from gacalc. The whole function/transform layer imports from `gacalc.transforms` (even names defined in `gacalc.functions` but re-exported there); only value types split by module (`base`/`g1`/`g2`/`g3`). Bonus: matches the book's doc-region listings, which already show these from gacalc's source. Surfaced pre-existing ch10 rot (`Vector2.e_1()`→`.e_1`, `scale_non_uniform_2d`, `.isclose`). (`2026/07/21/remove-mathutils-gacalc-facade.md`; migration groundwork in `2026/07/09/gacalc-math-migration.md`)

- **`rotate`/`rotate_x/y/z` are direct bindings of gacalc's `plane_rotation(a, b)`, plane derived once at import — not per-call wrappers.** The old façades hand-built `cos θ·a + sin θ·b` and re-derived the plane every call; `cayleyscene` calls `.at(t)` per edge per frame. Deriving the plane once: **160.6µs → 6.4µs (25×)**, and returns plain `float` instead of leaking a sympy `Float` (which had made every downstream demo op ~6× slower). `rotate_90_degrees` retired (= `rotate(radians(90))`). Orientation predicates moved into their sole consumer, the software rasterizer, computing the wedge `(v1^v2).coefficient(Bivector2.e_12)` directly. (`2026/07/09/plane-rotation-mathutils-adoption.md`)

- **gacalc's precise operator types (0.0.12/0.0.13) retired the `.coefficient(...)` spelling and `find_normal`'s reconstruction.** `(v1 ^ v2).coefficient(Bivector2.e_12)` became `.coeff_e_12` (the wedge now returns `Bivector2`), and `find_normal` returns **bare `bivector.dual()`** — the explicit `Vector3(coeff_e_1=…)` rebuild and `float()` casts were dropped (Bill's call). Display consequence, kept deliberately: a zero component can print as `-0.0` (the old path dropped zeros); three doctests show `coeff_e_2=-0.0` on purpose. Verification trap from the same work: `ty --python <prefix>` against a pip-installed gacalc gives false readings — use a venv/`PYTHONPATH` (see `tests-and-gates.md` §5). (`2026/07/22/dual-coefficient-cleanup.md`, `2026/07/22/precise-product-types-coefficient-cleanup.md`)

- **`is_parallel` → `is_parallel_and_same_orientation` (behaviour unchanged).** The old name disagreed with the GA sense — the predicate also requires same orientation, so the honest name states both. Deliberately did **not** switch the guard to a wedge test (Option B, deferred by Bill); the precise name + a call-site comment make the latent degenerate/anti-parallel-triangle gap *visible* instead of silently fixed. (`2026/07/19/is-parallel-ga-semantics.md`)

- **`shading._face_normal` reimplemented on `mathutils.find_normal` but keeps its tuple return.** It duplicated `find_normal`'s cross-product/CCW formula bit-for-bit (max diff 2.2e-16). The tuple return is deliberate: the GL boundary and indexing callers (`light_dir[i]`) want tuples, and adding `__getitem__` to the vector type was rejected — the course intentionally avoids treating vectors as indexable arrays. (`2026/05/26/shading-use-vector3d.md`)

- **Scale-transform inverse LaTeX renders the reciprocal `\frac{1}{m}`, not `S_{-m}`.** Matches `f_inv = vector*(1/m)`, applied consistently to all three scale inverses. Gotcha for re-introduction: `\\\frac` inside an f-string is backslash + form-feed (`\f`) + `rac`, not `\frac`. Latent because nothing rendered/tested inverse LaTeX. (`2026/05/26/fix-mathutils-latex-and-error-strings.md`)

- **`is_clockwise` was infinite-recursing** (called itself instead of `not is_counter_clockwise(...)`); fixed + regression test. Hidden indefinitely because it had no test and its `doc-region` marker was unused in any chapter — never exercised. The lesson: predicates with no test and no book-slice can harbor stack-overflow bugs forever. (`2026/05/26/fix-is-clockwise-recursion.md`)

- **The book's matplotlib-plot transforms were migrated onto gacalc (2026-08-04) — reversing the 2026-07-19 "don't rewrite" call under "Investigations that recommended NOT rewriting" below.** `plotsforbook/generate_plots.py` now uses gacalc's `translate`/`scale_non_uniform`/`rotate` (`plane_rotation`)/`compose`; the bespoke `accumulate_transformation` was replaced by a 6-line `_accumulate` over gacalc's `compose_intermediate_fns` (itself *ported from this book*). An `_apply(fn, xs, ys)` bridge (mirroring `nbplotutils._xy`) marshals `(xs,ys) ↔ Vector2` only at the matplotlib boundary, so all `plt.plot` plumbing stays byte-identical. **The `forwards`/`backwards` flag maps to gacalc's `relative_basis`** (`forwards=True ↔ relative_basis=False`), with the list passed as `reversed(procedures)` because gacalc's `compose` applies right-to-left — validated frame-for-frame against the old generator's doctests (worst delta 1.8e-15) *before* deleting them. `Geometry.points` kept as `(xs,ys)` arrays (not `list[Vector2]`) — lower pixel risk, same decoupling. The dead `plotutils/matplotgraphs.py` and the now-unimported bespoke `plotutils/mpltransformations.py` were both deleted. Gate: **170 figures pixel-identical (0 px each)** vs a HEAD-worktree baseline (no branch). No book-prose impact — the book consumes only the SVG output. (`2026/08/04/rewrite-book-plot-transforms-with-gacalc.md`, `2026/08/04/delete-dead-matplotgraphs.md`)

## The matrix / function stack

- **`pyMatrixStack.py` renamed to `matrix_stack.py`; both `N813` ruff exemptions deleted at the source.** The alias `import … as ms` was never the problem — the camelCase *module name* was what `N813` flagged. Done in **one commit, no compat shim**: the module holds mutable module-level state (`__modelStack__` etc.), so a double-import under two names would create two independent stacks. Zero book references. (`2026/07/19/rename-pymatrixstack-module.md`)

- **Five latent matrix-stack bugs fixed, incl. `get_current_matrix`'s silent `None` fall-through (five `if`s, no `else`) — now a `match` with `case _: raise`.** This is *the* worked example behind the "prefer `match` + `case _`" rule: every real `MatrixStack` member was handled, so it looked fine; the hole opened only for an unhandled member, and every caller indexed the result. Also: the `np.matrix`→`np.ndarray` migration is **not** find-and-replace — `multiply` does in-place slice assignment that behaves differently for `np.matrix` (which overloads `*` as matmul). Equivalence proven by *mechanically* reverting the one change (`np.array(`→`np.matrix(`) into a second module and diffing (max |Δ|=0.0), after a hand-written reference had earlier introduced a phantom 14.5-unit regression. Note the read/write asymmetry: reading a *derived* stack product still works; only *writing* one now raises. (`2026/07/18/pymatrixstack-bugs.md`)

- **The `mathutils.fn_stack` module global was silently splitting into two objects — root cause was a packaging omission, not the global.** With no top-level `src/modelviewprojection/__init__.py`, `find_packages(where="src")` returned `[]` and pytest imported modules under bare names, double-importing each run. The global is **deliberate pedagogy** (the Python analogue of OpenGL's implicit matrix stack, `literalinclude`d into ch16) — removing it / ContextVar / explicit-param were all rejected as perturbing taught code. Instructive dead-end: a loud import-guard (option E) was implemented and **reverted** — it couldn't distinguish pytest's harmless double-import from a harmful one (identical `sys.modules` signatures). The real gate found what an isolated prototype couldn't. Same `__init__.py` fix applied to gacalc. (`2026/07/19/fn-stack-global-fragility.md`)

- **`planar_shadow(matrix_stack, plane_eq, light_pos)` builds the SuperBible *directional* (parallel, `w=0`) shadow — not a point-light perspective shadow — and is deliberately NOT a Cayley-graph edge.** The transform collapses 3D onto a plane (rank 3, non-invertible), so it cannot be an `InvertibleFunction`; it lives in `matrix_stack.py` (in-place post-multiply, like `glMultMatrixf`), not `mathutils.py`, and the chapter that introduces it should say out loud that it is not a graph edge — that is the teaching moment. Matched to `chapt01/block/Block.py` / `math3d.cpp:1026` (whose `v_light_pos=(…,0.0)` confirms directional), byte-identical to an independent transcription (max |Δ|=0.0), guarded by 5 tests in `tests/test_matrix_stack.py` (the module's first test file). Two deliberate choices: (1) **directional over point-light** — the task's own prose sketched the point-light derivation, but the authoritative reference builds the `w=0` parallel matrix; Bill confirmed keep directional (2026-08-03), and switching to point-light is a one-line bottom-row change. (2) **excluded Block.py's `sign` negation** (an mvp CCW-winding / `w`-clip render hack, not part of the canonical `m3dMakePlanarShadowMatrix`) — the library builds the canonical matrix and the docstring documents the winding caveat so a call site can negate if its winding needs it. (`2026/08/03/planar-shadow-matrix.md`)

## Book & code-sync

- **The book includes code by MARKER (`doc-region-begin/end` + `:lineno-match:`), never by line number.** Editing a source file cannot "break" line numbers — Sphinx recomputes them at build. Consequence for drift audits: `literalinclude` snippets are **always live** (build-synced), so drift only ever lives in the *prose, captions, and hand-written doctest blocks* around them — that's where to look. `translate` is a module-level function returning an `InvertibleFunction` (vector addition wrapped), **not** a `Vector.translate()` method — book prose had claimed otherwise. (`2026/05/27/book-code-drift-ch1-6.md`; the marker mechanics are now in `CLAUDE.md`)

- **Some book listings are `literalinclude`d from GACALC's own source, docs-only (2026-07-20).** The vector/transform math lives in external gacalc, not this repo; the book still shows it via gacalc's doc-region markers. Two PyPI artifacts, same version: the **wheel** is the runtime dep, the **sdist** is unpacked to `/opt/gacalc-src` docs-only (never on `sys.path`, chosen over a git clone because it already carries the generated `g1/g2/g3/scalar.py` with markers baked in). The doc-region checker moved **into the container** because `_gacalc_src` only exists in the image. Editing such a listing means editing gacalc and releasing it. The editorial rule that decided *which* gacalc code the book shows: **white-box** (include the source) where the course narrates the code line by line (ch06's `InvertibleFunction` cluster); **black-box** (prose + pointer) where the author tells students not to stress the implementation (ch05/ch14 data types). (Now in `CLAUDE.md` and `book-and-docs-pipeline.md` §6; open follow-up `tasks/dangling-book-code-includes.md`)

- **The crossproduct demo was removed entirely** (`mathdemos/`, `notebooksrc/crossproduct.py`, `tests/test_crossproduct.py`) — it moved to the multivariate-math repo. Side effect: `ty check src` went **79 → 0**. texExpToPng build stays (the book's inlinetex extension uses the binary, independent of the demo). (`2026/07/09/remove-crossproduct-demo.md`)

## Ports — Code-the-Classics games

The 10 CtC ports sit on one clean-room `pgzero_gl` shim (GLFW + OpenGL 3.3 core). The **rule-set evolved**, so date order matters:

- **Original rule (2026-06 → 06-29): behaviour-faithful ports, annotations only, NO restructuring, NO ruff.** Games were still treated as line-by-line BSD-derivative copies diffable against upstream. Type-clean via `ty`; nullable-but-unguarded Actor attrs typed `Any` not `Optional` (games deref assuming non-null; `Optional` just relocates the error). (`2026/06/25/port-codetheclassics-vol1.md`, `.../vol2.md`, `2026/06/29/codetheclassics-types-and-docstrings.md`)

- **Rule relaxed (2026-07-08): behaviour-faithful, but STRUCTURE may modernize** — dataclasses, `match`, `@override`, precise types, ruff-formatted. Bill's call, because he owns all 10 games. "Behaviour-faithful" still means **same RNG call order, same update/draw order** (byte-identical gameplay). This is the doc that rewrote the `CLAUDE.md` rule. (`2026/07/08/ctc-dataclasses-and-dispatch.md`)
  - **Dataclass rules:** always `@dataclass(eq=False)` (generated `__eq__` would swap identity for field equality — games rely on identity). **Never dataclass a class whose base or subclasses are also dataclasses** (InitVars merge, breaking positional call sites) — convert stateful leaves over plain bases only. Keep explicit `__init__` when super-args are RNG-computed (preserves RNG order → byte-identical). The heterogeneous update/draw loops and ABC families are **deliberate curriculum** (the books teach OOP), not pgzero leftovers — keep them. (`2026/07/08/ctc-dataclasses-and-dispatch.md`)
  - **`match` only where EVERY branch is `subject == Enum.MEMBER`;** chains with a trailing non-enum branch stay `if/elif`. Enum cases must be **dotted** (bare name = capture-pattern footgun). Preserve deliberate upstream no-op fall-throughs. `@override` is high-value here — the whole dispatch hangs on override links, so it turns a renamed/typo'd base method from silently-dead dispatch into a type error (98 applied). (`2026/07/08/ctc-match-and-modern-python.md`, round 2 `2026/07/09/ctc-modernization-round2.md`)
  - **Enums that do arithmetic must be `IntEnum`, not `Enum`** (myriapod indexes/does modular math on `Direction`; `str(IntEnum)` since 3.11 is the plain number, so sprite-name construction stays byte-identical). Deliberately left as plain ints: soccer's 0-7 compass `dir` (arithmetic-native — an enum would fight the mechanic), kinetix brick-type ints (level data, not symbolic states). (`2026/07/09/ctc-modernization-round2.md`)

- **"Honest imports" cluster (2026-07-08): make imports reflect reality now that Bill owns the games** (drops the byte-faithful-to-upstream constraint; behaviour-faithful retained). Deleted the synthetic `pygame`/`pgzero` `sys.modules` impersonation modules (~130 lines) and their `ty: ignore[unresolved-import]` suppressions; replaced `from pgzero_gl import *` with explicit subsets (unmasking caught a real latent `gldraw.` NameError in soccer); hoisted function-local imports except the deliberate GL/PIL/renderer defers. Trap: the shim re-exports pgzero's `exit()` — an explicit import must include it or the builtin silently wins. (`2026/07/08/ctc-honest-imports.md`, `ctc-explicit-star-imports.md`, `ctc-imports-at-top.md`)

- **The shim `Vector2` subclasses `gacalc.g2.Vector2`; `vec * vec` RAISES.** pygame's `*`-means-dot clashes with gacalc's geometric product, so every `vec*vec` site was first converted to explicit `.dot()` (Phase A) and `Vector2.__mul__` made to raise on a vector operand — a missed site fails loudly, never silently changes meaning. Subclassing required an upstream gacalc generator change (subclass-preserving `type(self)(...)` ops) *and* a gacalc relicense to LGPL. Two permanent documented `invalid-method-override` variances (`dot`, `rotate`). Benchmark gate: 2.6%→3.4% of a 60fps frame at 200 actors — subclass accepted over facade. (`2026/07/08/ctc-vector2-deferral.md`) — **Note:** `CLAUDE.md` (2026-07-09) now says the games use `gacalc.g2.Vector2` *directly* with no shim vector subclass; the subclass here was superseded the next day. (`2026/07/09/codetheclassics-gacalc-math.md` records the cautious shim-delegation plan that was *exceeded* — gacalc grew `x/y/z` properties + quotient `/` in 0.0.8 instead.)

- **The shim's `Actor.__getattr__`/`__setattr__` magic was DELETED** and replaced with real static properties. Upstream pgzero uses open-world attribute magic because it teaches children; the 10 games are a **closed, enumerable corpus** (play-instrumented: zero getattr-misses across every game), so the machinery was pure per-frame overhead (plain write 844→10ns, 84×). Kept dynamic only where genuinely open + not hot (`keyboard`/`images`/`sounds`, first-touch cached). Incident: the new `pos` property collided with subclass `pos: InitVar` fields → renamed the InitVar to `spawn_pos` everywhere; added a **definitions gate** (`runpy.run_path` with `go` stubbed) because `py_compile` doesn't execute class bodies. Caught ~20 latent bugs. (`2026/07/09/ctc-shim-dynamism-audit.md`; local-type extension `2026/07/09/ctc-more-types.md` — module-level `game` typed `cast("Game", None)` with a documented "None only on title screen" invariant, chosen over 120 narrowing guards after a Fedora `ty` bump got stricter)

- **gacalc's value types became frozen (0.0.14); ~80 in-place coordinate writes converted to rebinding, proven behaviour-identical by a differential trace.** Two findings worth not rediscovering. **(1) The scope estimate in the task doc was wrong, and reading beat trusting it:** it predicted ~150 sites "plus a few demos and `util/cameracontrols.py`", but the demos, `assignments/`, and `cameracontrols` mutate their *own* plain-float `Vector`/`Vertex`/`Camera` dataclasses — 44 of the 182 raw grep hits — and were untouched. Likewise `self.x += …` on an `Actor` goes through Actor's own float property (backed by `ZRect`), not a gacalc vector. Only ~80 sites, all in six game files, were real. **(2) `ty` is only a partial oracle:** it flags a plain `v.x = …` as `invalid-assignment` (read-only property) but says **nothing** about an augmented `v.x += …`, so the sweep needs ty *and* a grep. Verification was a differential state trace — same seed, 300 frames of `update()` headless, canonical dump of every actor's numeric state — run as original-source-on-mutable-gacalc vs migrated-source-on-frozen-0.0.14: byte-identical for all six games (675–8604 trace lines each). Gotcha in building such a harness: an `id()`-keyed visited-set gives **false skips**, because `Actor.pos` returns a fresh `Vector2` per call and a freed temporary's id gets reused — check leaves before the cycle guard. Note on `_smoketest.py`: it was broken at the time (calling the deleted `pgzero_gl.pgzrun`) so it couldn't serve as the gate; **fixed 2026-07-25**, but deliberately still not wired into any gate — it remains a manual tool (`2026/07/25/fix-smoketest-broken-pgzrun.md`, and `tests-and-gates.md` §4 for the EGL env requirements). (`tasks/archive/2026/07/23/frozen-vectors-rebind-migration.md`; upstream `github.com/billsix/geometricalgebra`)

- **The freeze migration's deferred cleanup ran 2026-07-25:** 12 pure-aliasing defensive copies (`self.x = Vector2(*x)` where the source is already vector-typed) removed across beatstreets/kinetix/soccer/leadingedge together with the now-false "Vector2 is mutable, copied not by reference" comments; **2 copies kept** because they normalize `Any`/tuple-typed inputs; the `DEFAULT_*` module constants stay (removing one would re-trip ruff `B008`). Classifier rule recorded in `tests-and-gates.md` §6. (`2026/07/25/redundant-vector-defensive-copies.md`)

- **Audio: one miniaudio `PlaybackDevice` + a software-mixing callback (pygame.mixer's architecture), NOT one OS stream per voice.** Dropped `just_playback` for `miniaudio`. Root cause (found by diffing against untouched upstream + library source): just_playback opens one OS audio stream per voice, kept open forever to dodge a no-finalizer leak; leadingedge crossfades 40 looping engine samples → dozens of concurrent ALSA/PipeWire streams → clunk (separate devices can't sample-level crossfade) + freeze (stream-slot exhaustion blocking the game thread inline). An earlier 50Hz fade-thread fix was **disproven as the cure** (both symptoms persisted) but kept as correct semantics and folded into the callback. Now exactly one OS stream ever, so the freeze mechanism is structurally impossible. Not `pygame.mixer` because host SDL2-on-SDL3 breaks SDL audio; headless → graceful no-op. (`2026/07/09/leadingedge-audio-clunk-and-freeze.md`)

- **A second fixed-function `renderer_gl1.py` backend, selectable via `PGZERO_GL=1`, pixel-identical to the 3.3 renderer.** Runs on old/limited GL (software GL, Pi, remote X); also pedagogical — mirrors the book's demo19 fixed-function era. Tractable because the renderer was already behind a small interface (`draw_image`/`fill`/`set_clip`/…). Offscreen `pygame.Surface` is emulated as a **CPU RGBA buffer, not an FBO** — the games only need fills + sprite accumulation. (`2026/06/25/pgzero-gl-opengl1-renderer.md`, `.../port-codetheclassics-vol2.md`)

## Ports — SuperBible v4

- **Ported per-frame `sin`/`cos` immediate-mode mesh generation into shared `_primitives.py` builders that precompute once — but rendering stays immediate-mode.** Explicit constraint: **NO display lists or VBOs unless the C++ source already uses them** (faithfulness over performance); only *when the trig runs* changes. The plan's "one `build_cone` with optional stacks" was wrong on contact (three distinct tessellations exist) — builder makes only the shared fan body, demo-specific caps stay local. `build_octahedron` dropped (hardcoded literals, no trig, 3 inconsistent variants — couldn't be byte-faithful). Verified byte-identical via a GL-stub call recorder. (`2026/05/29/extract-data-generation.md`)

## Render pipeline & GL conventions

- **The Cayley graph is an explicit immutable/acyclic data structure (`CayleyGraph`/`Edge`/`path`) + a headless scene/animation engine; all seven viz demos rebuilt on it.** The seams everything hangs on: interpolation is an optional law on `InvertibleFunction` (composites recurse via `components`/`steps()`, not stored closures), and `inverse` *commutes* with `at(t)` so backward-walked edges animate. Camera placement == object placement (declare the camera edge once, walk it backward → one graph drives both imgui trees). The perspective/ortho squash stays a GPU shader step modelled as `NonInvertibleTransformation`, **not** an affine edge, because it's projective. `Frustum` (perspective) and `RectangularPrism` (ortho) are separate types — "the ortho is not a frustum." (`2026/06/03/cayley-graph-visualizations.md`)

- **`cayleyscene.to_matrix`'s float coercion is PERMANENT — do not revert it when gacalc-side fixes land.** The crash chain: gacalc's `magnitude()` is `sympy.sqrt` unconditionally → `rotor_from_vectors` → every vector a rotor touches carries sympy coefficients → numpy infers `dtype=object` → `np.linalg.inv` dies (`modelviewperspectiveprojection.py`). Four reasons the coercion stays regardless: numpy/GL need float64; gacalc may legitimately return sympy in symbolic use; `float(x)` is free when already float; it decouples mvp's rendering from gacalc's numeric-vs-symbolic policy. Guarded by `tests/test_focus_to_matrix.py`. (`2026/06/13/mvpviz-focus-failure.md`)

- **A default VAO is bound at startup and never unbound; VBO/VAO construction split into `make_vbo` + `make_vao([AttribSpec])`.** Fixes real macOS Core Profile support — VAO 0 is prohibited there. The original bug diagnosis ("shaders won't compile") was WRONG: compile/link need no VAO; the real failures are `glVertexAttribPointer`/`glEnableVertexAttribArray`/`glDraw*`. `AttribSpec` keeps `(stride, offset)` a coupled tuple deliberately (splitting them is a foot-gun). Shared-VBO dedup shows up naturally as repeated `vbo=` in the spec list. (`2026/05/27/vao-vbo-separation.md`)

- **Loose per-pipeline `program`/`u_*` globals grouped into frozen `@dataclass` pipeline structs — plain data containers only, no methods.** The `u_bs_*` prefix convention was already doing a struct's job; the dataclass makes program↔uniform ownership explicit without an OOP upgrade (keeps free functions free / procedural curriculum style). Students already know `@dataclass` from `mathutils.InvertibleFunction`. Kept the `u_` prefix (it still signals "uniform" at a glance). (`2026/05/27/demo21-22-pipeline-dataclasses.md`)

- **Viz shaders de-duplicated by identity `(color source) × (animated project()?)`, not by the object drawn.** Shaders were named after the object (triangle/ground/cube) but their real identity is the color/animation combo; `project()` was byte-identical across most. Unifying fixed a real bug (perspective `axis.vert` used `max(1.0,…)` and never animated). GLSL 330 has no `#include`, so composition is a forward-declared `vec4 project(vec4)` + snippet source appended at compile time. (`2026/05/27/mvpviz-shared-shaders.md`)

- **`upload_mvp`/`_upload_frustum` renamed to `set_uniforms`.** "Upload" is wrong for `glUniform*` — the spec verb is "specify"; it updates cheap driver-side program state, not GPU memory. Reserve "upload" for `glBufferData`/`glTexImage2D`/PBOs, which actually move bytes. Also dropped the `mvp` qualifier since the functions set a varying uniform list. (`2026/05/27/notes-uniform-terminology.md`)

## Investigations that recommended NOT rewriting

Kept because the *conclusion* (don't touch it) is a decision someone will otherwise re-propose:

- **[SUPERSEDED 2026-08-04] The matplotlib plot code should NOT adopt the GL side's `InvertibleFunction`/`Vector2` vocabulary.** This 2026-07-19 conclusion was **reversed** — Bill had the full migration to gacalc done 2026-08-04 (see "Math library & gacalc integration" above; 170 figures pixel-identical). Original reasoning, kept for the record: the book never shows this code (0 `literalinclude`/`doc-region` refs — build tooling, only its SVG output consumed), and the ugly nested-splat was one expression (50 of 51 sites already composed via a list). What changed the call: making the plot code speak the same math the book *teaches*, and gacalc having since absorbed the intermediate-composition logic (`compose_intermediate_fns`). (`2026/07/19/investigate-plotting-transform-model.md`, superseded by `2026/08/04/rewrite-book-plot-transforms-with-gacalc.md`)

- **Having migrated, KEEP the procedure *list* — do NOT collapse it into a single composed function (Bill considered and declined, 2026-08-04).** The book renders each transform step-by-step, so it needs the intermediate *prefix* compositions — a fold over an ordered sequence, which is exactly what gacalc's `compose_intermediate_fns(list, relative_basis)` consumes, so the list is the idiomatic input, not a wart. Collapsing `[p1,p2,p3]` into `compose([...])` buys nothing — a composed gacalc function retains its parts (`.components`/`.steps()`), so you'd decompose it straight back — and is *risky*: `steps()` flattens nested composites to leaves (changing the frame count for any step that is itself a composite), and `at(t)` interpolates continuously rather than in discrete whole-step prefixes. (`2026/08/04/rewrite-book-plot-transforms-with-gacalc.md`)

- **`nbplotutils`' `global axes` kept implicit, backed by a `contextvars.ContextVar` + one `_current_axes()` accessor; zero call sites changed.** ~150 teaching-facing call sites would lengthen with an explicit `axes` param, versus only 8 `create_graphs` blocks — not worth it in teaching code (the short call site mirrors pyplot's `gca()`). The accessor and the ContextVar backing turned out to be the same edit, so the cheap fix and the better mechanism weren't a trade-off. Accepted cost: the dependency stays invisible in signatures. (`2026/07/19/plotting-global-axes-design.md`)
