### 2. VAO/VBO separation — task #43 ✅

Plan: `/mvp/plans/vao-vbo-separation.md`. Three phases all done.

**Phase A** — macOS unblock. Default-VAO bind at startup,
`glBindVertexArray(0)` removed everywhere. Touched:
- `/mvp/mvpVisualization/_pipeline.py` (in `setup_window`)
- `/mvp/mvpVisualization/coordinatesystems`, `model`, `pushmatrix`,
  `modelview2d`, `modelvieworthoprojection`,
  `modelviewperspectiveprojection` (per-demo render fns)
- `/mvp/src/modelviewprojection/demo21/demo21.py` (in
  `impl_glfw_init`)
- `/mvp/src/modelviewprojection/demo22/demo22.py` (module scope after
  `make_context_current`)
- `modelview/modelview.py` skipped — it's GL 2.0 fixed-function, no
  VAOs.

**Phase B** — conceptual refactor. Introduced three primitives:
```python
@dataclass(frozen=True)
class AttribSpec:
    vbo: int
    location: int
    size: int
    layout: tuple[int, int]   # (stride_bytes, offset_bytes)

def make_vbo(data, usage=GL_STATIC_DRAW) -> int: ...
def make_vao(attribs: list[AttribSpec]) -> int: ...
```

In `_pipeline.py`, the old `make_triangle_vao` / `make_lines_vao` are
now thin wrappers around these (so visualization demos didn't need
changes). In demo21 + demo22, the new primitives are used directly:
- demo21 paddle position VBO is now shared between paddle1 and
  paddle2 (deduplication win: 7 → 6 VBOs).
- demo22's interleaved [pos3, normal3, uv2] layout is described
  with three `AttribSpec`s at one site (`_interleaved_attribs`),
  visible at the source level.

**Phase C** — sweep. Audited every `glDraw*` site for an upstream
non-zero VAO bind in the same function (38 sites, all good). Removed
unused `all_vaos`/`all_vbos` registries from demo22 (dead code —
demo22 has no GL-cleanup pass before terminate).

### 3. Pipeline-state dataclasses — task #41 ✅

Plan: `/mvp/plans/demo21-22-pipeline-dataclasses.md`.

Decisions made with Bill:
- Keep `u_` prefix on uniform fields.
- Don't pin attribute locations via shader `layout(location=N)` — out
  of scope.
- Preserve `_using_shadow_map` flag in demo22 — regrouping only.

**demo21**: 11 ungrouped globals → 2 dataclass instances
(`TrianglePipeline`, `GroundPipeline`) constructed by
`_build_triangle_pipeline()` / `_build_ground_pipeline()` and
referenced as `triangle.u_mvp` etc.

**demo22**: ~30 ungrouped globals → 5 dataclass instances:
- `main` (10-field MainPipeline) — lit + textured pass.
- `block_shadow` (12-field BlockShadowPipeline) — same scene draw,
  consumes shadow map.
- `shadow_depth` (2-field) — depth-only render from light POV.
- `shadow_view` (2-field) — fullscreen quad depth-debug overlay.
- `shadow_res` (3-field ShadowResources) — FBO + depth_tex +
  debug_tex.

Two automation bugs encountered and fixed:
- **Double-prefixing**: bulk regex applied
  `u_use_lighting → main.u_use_lighting` *after*
  `u_bs_use_lighting → block_shadow.u_use_lighting`, producing
  `block_shadow.main.u_use_lighting`. Reverted with a follow-up
  `block_shadow\.main\. → block_shadow\.` substitution.
- **Kwarg over-rewriting**: kwargs like `u_mvp=GL.glGetUniformLocation(...)`
  inside `MainPipeline(...)` constructors got prefixed to
  `main.u_mvp=...` (invalid syntax). Reverted via
  `\bprefix\.\w+=` → `\w+=` regex.

### 4. Side-effect fixes (related but not the main task)

- **demo21 missing `import os, sys`** — pre-existing latent bug,
  surfaced when Bill ran `python demo21.py` directly. Fixed.
- **PyOpenGL `glValidateProgram` rejects multi-typed samplers on
  macOS** — block_shadow_program in demo22 has both
  `sampler2D tex` and `sampler2DShadow shadowMap`; both default to
  unit 0 at link time, before the app calls `glUniform1i` to assign
  distinct units. PyOpenGL's `compileProgram` runs the validator
  eagerly. Fix: pass `validate=False` to all three `compileProgram`
  call sites in demo21 + demo22. Saved to memory:
  `feedback_macos_glvalidateprogram_samplers.md`.
