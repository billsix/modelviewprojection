### McNopper packaged as a standalone Python distribution

This is the **biggest layout change of the session**. Tree was
restructured from:

```
/mvp/ports/McNopper/_common.py
/mvp/ports/McNopper/example13/example13.py
/mvp/ports/McNopper/media/...
```

to:

```
/mvp/ports/McNopper/                        (package root)
├── pyproject.toml                          (name=mcnopper, v0.1.0, MIT)
├── setup.py                                (minimal shim)
├── requirements.txt                        (PyOpenGL/glfw/imgui-bundle/numpy)
├── Makefile                                (image/shell/run N=NN/list/wheel/sdist/clean)
├── Dockerfile                              (Fedora 44 + Mesa, mirrors /mvp's)
├── LICENSE / README.md / .gitignore / run.sh
├── entrypoint/{entrypoint,shell,loadpackages}.sh
└── src/
    └── mcnopper/
        ├── __init__.py                     (run(n), demo_count, demo_titles())
        ├── _cli.py                         (entry point: `mcnopper`)
        ├── _common.py                      (was at McNopper/_common.py)
        ├── media/                          (was at McNopper/media — 290 MB)
        └── example01/__init__.py + example01.py + *.glsl
        └── … through example47/
```

Both flows work:
- **Dev mode** — `python src/mcnopper/example13/example13.py` still
  works; the `sys.path.insert(..., parent.parent)` hack in each demo
  resolves `_common.py` one dir up exactly as before.
- **Package mode** — `pip install -e .` (or build the wheel) gives a
  `mcnopper` console-script. `mcnopper list` reads docstrings via
  `ast` so it works without OpenGL/glfw available. `mcnopper 13`
  uses `runpy.run_module(..., run_name="__main__")` to fire the
  demo's existing `if __name__ == "__main__":` block — no per-demo
  refactor was needed.

`find_media` in `_common.py` was updated to consult
`importlib.resources.files("mcnopper")/media` as the last fallback
so the bundled asset tree is reachable post-install.

## Standing rules I confirmed this session

- Don't trade fidelity for performance in ports (memory note,
  cited at example 37 reset to 640×480 earlier in port history).
- Use imgui controls, not keyboard shortcuts, as primary input.
- Always `glGetUniformLocation` — don't hardcode 0.
- macOS: bind a default VAO post-context-creation; pass
  `validate=False` to `compileProgram` (multi-sampler validators).
- For `/mvp/ports/`, no hardcoded absolute paths in find-media chains
  (use env-var → script-dir → sandbox fallback). The new
  `importlib.resources` fallback I added preserves this rule —
  there's still no hardcoded `/mvp/...` anywhere.
- PyPI publishes, container pushes, and any other
  visible/irreversible action need Bill's explicit per-upload
  approval — don't batch them.

## Things future-me should NOT do

- Don't revert the McNopper restructure. Bill explicitly asked for
  the standalone package layout this session.
- Don't introduce relative imports inside demo files. The current
  `sys.path.insert(...); import _common as C` pattern keeps both the
  dev-mode script-execution path and the package-mode `runpy`
  dispatch working. Switching to `from .. import _common` breaks
  direct script execution.
- Don't add types to local variables that aren't obvious from
  context. Partial coverage is fine. `Any` is a smell — leave it
  bare instead.
- Don't run mypy on the McNopper code. PyOpenGL has no stubs; the
  output is noise.
