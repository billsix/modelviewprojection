Description
^^^^^^^^^^^

Early in this book we used the :term:`stencil buffer <Stencil Buffer>`, but didn't go into
much detail about it.  Each :term:`pixel <Pixel>` in the :term:`framebuffer <Frame Buffer>` is a :term:`fragment <Fragment>`,
which is more information than just the color to be drawn.

.. figure:: _static/ccbysa3.0/williamsix/fragment.png
    :class: no-scale
    :align: center
    :alt: Fragment
    :figclass: align-center

.. figure:: _static/depthbuffer.jpg
    :class: no-scale
    :align: center
    :alt: depthbuffer
    :figclass: align-center


Besides the color, there is also

* :term:`Stencil buffer <Stencil Buffer>`, being true or false, to specify whether subsequent OpenGL calls
  should affect this :term:`fragment <Fragment>` or leave it alone
* Depth - When an object in :term:`NDC <Normalized Device Coordinates>` is drawn, the color is updated to the new
  value, but the z-component of the NDC is placed into the :term:`depth buffer <Depth Buffer>`.
  When a new object is drawn at this pixel later, its Z value will
  be compared to the existing Z value, to determine which object is in
  front.  If the new object is farther away from the camera than the
  already-draw object, then the :term:`fragment <Fragment>` will not be updated.
* Alpha, for transparency, which we have not yet covered.

For a history of what 3D programming for game systems was like
without having a :term:`z-buffer <Z-buffering>`, take a look at some history of
the Nintendo_ 64, and comments on hacker_ news about it.

.. _Nintendo: http://shmuplations.com/mario64/
.. _hacker: https://news.ycombinator.com/item?id=12558589


Use the :term:`depth buffer <Depth Buffer>` to make further objects hidden
if nearer objects are drawn in front



#. Set the clear depth to -1 (just like clearcolor, it is the default depth on a given :term:`fragment <Fragment>` (pixel).

#. Set the depth func, i.e. the test to see if the newly drawn object should overwrite the color in the current :term:`fragment <Fragment>` or not.

#. Enable the :term:`depth test <Depth Test>`.

With the :term:`depth test <Depth Test>` enabled, the square is now correctly hidden behind
paddle1 — even though it is still drawn *after* the paddle.  In the previous
chapter the square (translated by -1, so behind paddle1) was wrongly drawn
over it, because without a :term:`depth buffer <Depth Buffer>` the object drawn last clobbers the
color of whatever was already at that pixel.  Now each :term:`fragment <Fragment>` also carries
its depth, and ``GL_GREATER`` keeps a newly drawn fragment only when it is
nearer than the value already in the :term:`depth buffer <Depth Buffer>`, so the farther square no
longer overwrites the nearer paddle.  The previous chapter's manual workaround
of reordering the draw calls is no longer needed.
